Функціональні вимоги для UC-7, UC-7.1, UC-7.2, UC-7.3:


REQ-1: Користувач МОЖЕ авторизуватись через JWT токен

REQ-2: КОЛИ користувач намагається змінити оголошення система ПОВИННА перевірити чи авторизований користувач є його власником

REQ-3: ЯКЩО користувач який намагється змінити оголошення не є його власником система ПОВИННА відхилити запит

REQ-4: користувач МОЖЕ заборонити бронювання апартаментів на вказані дати

REQ-5: КОЛИ користувач створює/змінює оголошення система ПОВИННА перевірити чи відповідають змінені поля обмеженням

REQ-6: КОЛИ користувач змінює вартість апартаментів система НЕ ПОВИННА змінювати вартість вже створених бронювань

REQ-7: КОЛИ користувач створює оголошення система ПОВИННА перевірити чи вказані всі необхідін поля

REQ-8: ЯКЩО користувач намагаєтсья створити оголошення у якому відсутні необхідні поля система ПОВИННА відхилити запит

REQ-9: ЯКЩО користувач створює коретне оголошення система ПОВИННА встановити його статус на "active" 

REQ-10: ЯКЩО користувач знімає апаратмент з оренди система ПОВИННА встановити його статус на "inactive"

REQ-11: ЯКЩО користувач видаляє арартамент система ПОВИННА змінити поле is_deleted на True

REQ-12: КОЛИ система перевіряє доступність апартаменту вона ПОВИННА враховувавти дату заїзду та не враховувати дату виїзду як зайняту ніч

REQ-13: ЯКЩО діапазон дат який власник намагається заблокувати перетинається з існуючим бронюванням система ПОВИННА відхилити запит

REQ-14: ЯКЩО запит на блокування дат та запит на їх бронювання обробляються одночасно система ПОВИННА виконати лише один запит, а інший відхилити
